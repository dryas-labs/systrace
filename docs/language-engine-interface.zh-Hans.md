# 语言引擎接口

[English](language-engine-interface.md) | **简体中文**

Systrace 通过一个语言引擎提供者，将保存模型工具和编辑器接到同一个 language engine（语言引擎）。
这是内部 TypeScript 接口，不是新公开网络协议，也不表示任意引擎无须接入工作就能直接替换。

## 接口与实现

| 组件                     | 职责                                                         |
| ------------------------ | ------------------------------------------------------------ |
| `LanguageEngineProvider` | 后端身份、接口版本、默认引擎版本、模型后端工厂与语言服务描述 |
| `LanguageBackend`        | 引擎启动、保存模型验证、模型查询、独立标准库模型与关闭       |
| `LanguageServiceBackend` | LSP 版本命令参数和输出核对、启动参数/环境、标准库文档协议    |
| `ProjectSession`         | 保存文件、不可变快照、项目修订、请求队列、结果上限与分页     |
| 后端实现                 | 原生进程通信、RPC 格式、所需能力、诊断映射与原生查询转换     |

接口位于 `packages/engine-adapter/src/backend.ts`、`provider.ts` 和 `language-service.ts`，
引擎专用实现细节位于 `packages/engine-adapter/src/backends`。产品的默认选择集中在
`packages/engine-adapter/src/default-engine.ts`，通过 `DEFAULT_LANGUAGE_ENGINE_PROVIDER` 导出。

`interfaceVersion: 1` 表示适配层接口版本，与经过配置核对的原生引擎发行版本无关。
提供者和语言服务的身份与接口版本必须一致。`createLanguageBackend(provider, options)` 还会检查
创建的模型后端与提供者身份及支持的接口版本一致。API 和 LSP 仍是独立进程；共享提供者不会合并模型状态。
系统不会回退到另一个引擎。

## 模型后端操作

| 操作                                    | 返回值或作用                           |
| --------------------------------------- | -------------------------------------- |
| `start(signal?)`                        | 引擎名称/版本和声明的产品能力          |
| `validate(documents, signal?)`          | 输入源码对应的模型句柄、诊断与验证证据 |
| `openLibrary(signal?)`                  | 独立内置标准库模型的句柄               |
| `findElement(model, input, signal)`     | 匹配的模型元素及明确限制               |
| `describeElement(model, input, signal)` | 模型描述及明确限制                     |
| `libraryLookup(model, input, signal)`   | 标准库查询/浏览结果及明确限制          |
| `close()`                               | 回收后端会话                           |

这些操作支撑现有 保存模型操作 `validate`、`find_element`、`describe_element`、`library_lookup`，
工具输入格式与现有返回行为保持不变。公共接口提供语言操作与不透明模型句柄，
原生 RPC 名称、任意 RPC 调用和原生模型标识留在后端实现内部。

该接口用于语言分析，不包含执行模型、仿真、TypeScript 解析器或第二套名称解析器。

## 身份与快照范围

`ModelHandle` 是创建它的后端持有的不透明对象，绑定该后端的进程代数。调用方必须保留返回对象，
不能根据可见的代数值自行构造句柄。其他实例或上一进程代数的句柄无效；代数是生命周期信息，
不是跨引擎通用的模型标识。

`ProjectSession` 将模型结果关联到保存快照和项目修订，在操作后重读源码，项目变化时拒绝结果。
查询游标还绑定查询参数和后端代数；重启或项目变化后需要重新查询。
标准库查询使用独立模型，防止项目声明遮蔽内置库结果。

元素 ID 与限定名描述所属后端的模型；不承诺跨编辑、重命名、引擎重启或引擎替换保持稳定。
`nativeKind` 和原始诊断详情等字段保留提供者专有含义；本接口没有建立通用元模型词汇体系。

## 证据与失败行为

诊断保留严重性、原文、源码位置、类别和原生详情；各后端的类别映射留在各自实现内。
未知类别仍为 `UNCLASSIFIED`；移动映射文件不改变映射本身。

公开 API 诊断的 `line` 与 `column` 分别采用从 1 开始的行号和 UTF-8 字节列号，`0` 表示未知。
原生详情保留。这套位置与 LSP 位置分开，后者遵循 LSP 协议及协商的位置编码；调用方不能把
字节列号直接当作编辑器字符偏移。

验证证据包含标准库身份、解析/库加载/名称解析的完整性、已执行和未证明的检查。
当前配置的语言引擎 API 不认证这些完整性字段，也不能独立标识库版本，因此前者仍为 `unknown`、
后者仍为 `null`。公开结果有错误时继续为 `errors`，否则为 `incomplete`。
通信成功、模型加载或查询有结果，都不证明完整验证或工程正确性。

不支持某项操作，与查询歧义/暂不可用、响应格式错误、陈旧句柄、取消和超时是不同情况。
部分答案明确列出限制；失败不能变成空的成功答案，能力声明也不能代替独立一致性证据。

## 编辑器与标准库文档

编辑器补全、悬浮和跳转继续使用标准 LSP。语言服务描述提供版本核对、启动参数/环境，以及包含
URI scheme、能力检查、请求构造和响应解码的标准库文档协议。
其中 `storageKeyPrefix` 为恢复的库文档提供稳定且由提供者区分的存储命名空间，避免其他后端复用
同一个持久化身份。当前服务描述保留现有存储命名空间。
扩展负责各项目的编辑器 URI、取消、超时、刷新，以及拒绝已被替换连接的旧内容。

原生标准库 URI 格式、能力检查、请求名称与内容解码由服务描述负责。
编辑器文档提供器通过语言引擎接口使用这些描述。

LSP 可以分析未保存内容，保存模型 API 分析保存文件。配置引擎版本一致不意味着两者快照相同，也不独立认证内置库身份。

## 后端接口要求

提供者同时提供模型与语言服务接入。实现必须检查接口版本，遵守句柄归属和生命周期约束，保持查询与
验证证据的含义，并通过适用的原生引擎与编辑器宿主测试。

注入小型后端的接口测试只能检验产品行为和依赖边界，不能证明语言一致性或性能。
当前架构见[产品架构](architecture.zh-Hans.md)，引擎选择见 [Language engine](language-engine.zh-Hans.md)。

旧 `engine.ts` 的底层传输导出保留用于兼容已有开发客户端，仍属于后端专用接口；新增产品代码应使用语言引擎接口。
